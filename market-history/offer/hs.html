Everything else is read live from the code that actually runs — engine.js → HS_FACTORS / HS_FLAVOUR. Change a dial in the code and reload — it moves here too.

Base — the part we measure

A weighted mean, not a sum — that's the whole trick. A factor we can't read (no sqft, unranked town) drops out of the top and bottom of the fraction, so it neither helps nor hurts; it just makes the rest count for proportionally more. That is "don't penalise a missing field" done with arithmetic instead of good intentions. Each factor scores 0→1 on the curve shown, then counts for its weight.

Flavour — the part we read off the copy

Points added or subtracted only when the words are actually there — a missing mention never docks a house. Mined from the listing text, except the last block, which is what we saw by watching between runs. The whole sum is capped, because a chatty agent writes a better-sounding listing for the same house.

Confidence

Shown next to every score, never hidden. How much of the model actually ran — two houses at HS 78 aren't the same claim if one scored on half the factors.

The scale

Base is scaled to 88 so flavour has real room. So structured data alone tops out at 88, and 100 means excellent fundamentals AND everything you want is actually written down — rare, and it says something.
